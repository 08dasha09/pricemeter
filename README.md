# Pricemeter

Вебресурс для аналізу динаміки цін на побутову техніку в українських інтернет-магазинах із виявленням
недостовірних знижок.

Покупець бачить лише ціну «на зараз». Магазини ж нерідко піднімають ціну перед акцією, а потім
«знижують» її до попереднього рівня. Pricemeter щодня збирає ціни з кількох магазинів, накопичує історію й
показує, як ціна змінювалась насправді. Мета — вердикт «ціна нижча за звичайну / звичайна / завищена» та
позначки штучних знижок.

> Навчальний проєкт (дипломна робота). Дані збираються лише з публічних сторінок із дотриманням
> `robots.txt` і паузою ~3 с між запитами до сайту.

## Можливості

- **Збір цін** із **Moyo, Цитрус, Епіцентр, Eldorado**: пральні машини, холодильники, посудомийні машини, пилососи,
  мікрохвильові печі. Розбір розмітки Schema.org (JSON-LD, мікророзмітка) та даних сторінки; щоденний обхід
  (04:00 за Києвом), пропущений — надолужується після старту; журнал запусків і попередження про помилки магазину.
- **Історія цін** — ціна, заявлена «стара» ціна, наявність; інтервали незмінного стану. На графіках видно, де ціну
  підтверджено обходом, а де магазин не обходили (пунктир) чи товару не було (розрив).
- **Зіставлення товарів між магазинами** («Samsung WW80T4040CE1UA» і «Пральна машина Samsung WW80T4040 CE1/UA» —
  один товар): бренд, код моделі, TF-IDF назв, кластеризація; ручна модерація й виправлення зі сторінки товару;
  розмітка пар і Precision / Recall для оцінки якості.
- **Вердикт щодо ціни** — «нижча за звичайну / звичайна / завищена» за історією магазину (перцентиль за квартал) і
  ринком (медіана інших магазинів), з поясненням і останнім зниженням.
- **Недостовірні знижки** — акційна ціна на рівні ринку, завищена «стара» ціна, та сама ціна без акції в інших
  магазинах; частка недостовірних знижок по магазинах і категоріях.
- **Магазини й категорії** — індекс цін магазину (наскільки дорожчий чи дешевший за інші), як часто він найдешевший.
- **Підписки** — «Стежити за ціною» з бажаною ціною; сповіщення про реальне зниження (лист або запис на сайті).
- Вхід і реєстрація, адмін-сторінки лише для адміністратора; світла й темна тема, адаптивна верстка.

## Швидкий старт

**Потрібно:** JDK 25, Docker Desktop (для PostgreSQL і тестів). Maven окремо не потрібен — є `mvnw`.

```bash
# 1. База даних — PostgreSQL 16 у Docker на порту 5433
docker compose -f docker/docker-compose.yml up -d

# 2. Застосунок — http://localhost:8080
./mvnw spring-boot:run          # Windows: mvnw.cmd spring-boot:run

# 3. Тести (потрібен запущений Docker — Testcontainers піднімає окремий PostgreSQL)
./mvnw test
```

Схема БД створюється автоматично міграціями Flyway під час старту. Після першого запуску база порожня —
відкрийте http://localhost:8080/admin/crawl і натисніть **«Обійти всі зараз»** (по 20 товарів на категорію,
кілька хвилин) або запустіть обхід окремої категорії.

**Адміністратор.** Сторінки обходу й зіставлення (`/admin/**`) — лише для адміністратора. Обліковий запис
`admin@pricemeter.local` створюється під час першого старту; пароль — зі змінної середовища `ADMIN_PASSWORD`, а якщо
її немає — генерується й один раз виводиться в лог (`Created admin account … with generated password …`). Задати або
змінити пароль: запустити застосунок зі змінною `ADMIN_PASSWORD`. Вхід — http://localhost:8080/login; з галочкою
«Запам'ятати мене» вхід зберігається 30 днів і після перезапуску.

### Застосунок у Docker (рекомендовано для щоденного збору)

Щоб застосунок не залежав від відкритого терміналу, запустіть його контейнером — він стартуватиме разом із
Docker:

```bash
docker compose -f docker/docker-compose.yml --profile app up -d --build   # http://localhost:8080
docker logs -f pricemeter-app                                               # лог (пароль адміністратора — тут)
docker compose -f docker/docker-compose.yml --profile app down              # зупинити (дані БД лишаються)
```

Пароль адміністратора, SMTP тощо — у файлі `docker/app.env` (необов'язковий, не потрапляє в git), напр.
`ADMIN_PASSWORD=...`. Після змін у коді — та сама команда з `--build`. Поки працює контейнер, `mvnw spring-boot:run`
не запуститься (порт 8080 зайнятий).

**Пропущений обхід надолужується сам:** якщо після старту застосунку виявиться, що останній успішний обхід був
понад 20 год тому, а обхід за розкладом (04:00) не скоро, — через 2 хв запуститься повний обхід. Тобто для
накопичення історії достатньо, щоб застосунок запускався хоча б раз на добу.

Повний обхід можна запустити й вручну: http://localhost:8080/admin/crawl → **«Обійти всі зараз (по 200)»**
(≈ 1 год; зіставлення товарів запускається автоматично після обходу).

## Сторінки та API

| Адреса | Що там |
|---|---|
| `/` | головна: пошук, категорії, «реальні знижки сьогодні» й «підозрілі знижки» |
| `/products`, `/products/{id}` | товари; сторінка товару — ціни в магазинах, графік, вердикт, знижки, «Стежити» |
| `/discounts` | недостовірні знижки й частка по магазинах |
| `/shops/{code}`, `/categories/{code}` | індекс цін магазину, де дешевше в категорії, знижки |
| `/offers` | список пропозицій із пошуком і фільтрами |
| `/offers/{id}` | пропозиція: поточна ціна, графік, зміни ціни |
| `/login`, `/register` | вхід і реєстрація |
| `/account/subscriptions` | мої підписки: поточна найнижча ціна, бажана ціна, останні сповіщення |
| `/admin/crawl` | розклад, ручний запуск обходу, журнал запусків |
| `/admin/matching` | зіставлення товарів: пропозиції на перевірці, ручні рішення |
| `/admin/labeling` | розмітка пар «той самий товар / різні» для оцінки зіставлення |
| `/admin/matching/evaluation` | якість зіставлення: Precision / Recall / F1, пороги, помилки |
| `/actuator/health` | стан застосунку; `crawler` — DOWN, якщо успішного обходу не було 48 год (деталі — адміністратору) |
| `GET /api/offers/{id}/history?period=WEEK\|MONTH\|QUARTER\|ALL` | денний ряд цін (JSON) |
| `GET /admin/crawl/categories` | які категорії вміє обходити кожен магазин (JSON) |
| `POST /admin/crawl/{shop}/{category}?limit=N` | синхронний обхід категорії, відповідь — звіт (JSON) |

```bash
curl -u "admin@pricemeter.local:$ADMIN_PASSWORD" -X POST "http://localhost:8080/admin/crawl/moyo/washing_machines?limit=20"
curl "http://localhost:8080/api/offers/5/history?period=QUARTER"
```

> `/admin/**` — лише для адміністратора (форма входу або HTTP Basic, як у прикладі). REST `/api/**` — відкритий.

## Налаштування

Основне — у `src/main/resources/application.properties`; будь-яку властивість можна перевизначити змінною
середовища (напр. `CRAWLER_SCHEDULE_ENABLED=false`).

| Параметр | За замовчуванням | Опис |
|---|---|---|
| `DB_URL` / `DB_USER` / `DB_PASSWORD` | `jdbc:postgresql://localhost:5433/pricemeter` / `pricemeter` / `pricemeter` | підключення до PostgreSQL |
| `crawler.schedule.enabled` | `true` | щоденний обхід |
| `crawler.schedule.cron` | `0 0 4 * * *` | час обходу (за Києвом) |
| `crawler.schedule.catch-up` / `-after` / `-delay` | `true` / `PT20H` / `PT2M` | надолужити пропущений обхід після старту |
| `crawler.schedule.limit-per-category` | `200` | скільки товарів на категорію за розкладом |
| `crawler.deactivate-after-days` | `7` | через скільки днів без появи пропозиція стає неактивною |
| `crawler.http.respect-robots-txt` | `true` | дотримання `robots.txt` |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | `admin@pricemeter.local` / — | обліковий запис адміністратора |
| `SPRING_MAIL_HOST`, `SPRING_MAIL_PORT`, `SPRING_MAIL_USERNAME`, `SPRING_MAIL_PASSWORD` | — | SMTP для листів підписникам (напр. Gmail: `smtp.gmail.com`, `587`, пароль застосунку, плюс `SPRING_MAIL_PROPERTIES_MAIL_SMTP_STARTTLS_ENABLE=true`); без них сповіщення лише в лозі й на сторінці «Мої підписки» |

Порт БД — **5433**, щоб не конфліктувати з локальним PostgreSQL на 5432.

## Як це працює

```
 CrawlScheduler / надолужування ──► CrawlLauncher ──► адаптери магазинів ──► offer, price_snapshot
 (04:00 або після старту)           (магазини паралельно)                    (каталог, історія інтервалами)
                                          │ після обходу
                                          ▼
                              зіставлення (product) ──► сповіщення підписникам
                                          │
                                          ▼
            аналітика на льоту: ринок товару, вердикт, недостовірні знижки, індекс цін магазинів
                                          │
                                          ▼
                     Веб (Thymeleaf + Chart.js) і REST API /api/products, /api/offers
```

- **Стек:** Java 25, Spring Boot 4.1 (MVC, Thymeleaf, Data JPA, Security, Actuator, Mail), PostgreSQL 16, Flyway,
  Jsoup, ShedLock, Chart.js; тести — JUnit 5, Testcontainers (один контейнер на прогін, ≈ 1 хв).
- **Архітектура:** модульний моноліт — `catalog`, `crawler`, `pricehistory`, `matching`, `analytics`,
  `fakediscount`, `user`, `subscription`, `web`, `api`.
- Чому немає Rozetka, Foxtrot, Allo, Comfy: вони закриті антибот-захистом (Cloudflare), а обходити його
  проєкт не буде.
